# 日本の地名の由来ナレッジベース — メタ設計

## 1. 目的と範囲

日本の地名について、「その名前はどこから来たのか」を、一次文献とその記載が確認できる資料まで遡って記録するナレッジベース。対象は都道府県から始め、市区町村へ拡張する。単なる語源の断定集ではなく、次を区別して残すことを目的とする。

- 文書で確認できる歴史的事実
- 地域に伝わる民間伝説・伝承（事実とは分けて記録し、面白さはここにもある）
- 諸説が対立しているもの、資料では決められないもの

提供形態は出典つき構造化レコード（正本）と、そこから生成するインタラクティブ地図つき静的サイト。地図で都道府県・市区町村をクリックすると、その地名の由来が表示される。

## 2. ユーザーの途中資料から引き継ぐエッセンス

出発点の資料（都道府県47件の一覧表、北海道〜静岡と愛媛まで詳述済み）が持っていた優れた設計は、そのまま型として採用する。

1. **県名の由来と「地名そのものの由来」を分けて追う**：県名は多くの場合、郡名・藩名・城下町名・県庁所在地名の転用であり、「なぜその名前が県名に選ばれたか」と「元の地名はなぜそう呼ばれるか」は別の問いとして記録する（例：神奈川県＝外交拠点としての神奈川の名を掲げる必要があったという選定理由／神奈川という地名自体は郷名と川名の転訛）。
2. **廃藩置県時の扱いの類型を持つ**：新規命名（北海道・東京・静岡）／一部の地名の転用（青森・岩手・宮城ほか郡名・町名由来）／藩名の継承（秋田・福島ほか）／文献からの引用命名（愛媛＝『古事記』の愛比売）／不明。この類型は `naming_type` として全レコードに持たせる。
3. **初出を一次文書で示す**：『続日本紀』『和名類聚抄』『常陸国風土記』『大和物語』、藤原京出土木簡、鶴岡八幡宮文書、詔書・太政官布告など、「主な文書」欄が指していた一次文献を、各主張の出典にまで落とし込む。
4. **位置のずれを明記する**：現在の自治体と往時の地名の位置がずれる例（埼玉の原点は行田市埼玉であって現在のさいたま市ではない、青森の原点は現在の青森市青柳あたり）を落とさない。
5. **「定かではない」を臆さず書く**：語源が未確定のものは未確定として残す。埋めるための創作はしない。

引き継がない点（KB化にあたって直す点）：事実と伝説が一つの文章に混在していること、出典が主張単位でなく欄単位であること、空白行（未調査の県）が「未調査」と「存在しない」の区別なく残っていること。

## 3. 3層構造

| 層 | 内容 |
|---|---|
| L1 正本 | 構造化レコード（YAML）。全ての主張に出典キーと証拠レベルと種別（事実／伝説）を持つ |
| L2 文献コーパス | 一次文献の書誌と、記載内容の自作要約。原文の長文転載はしない |
| L3 派生物 | 静的サイト、地図データ、機械可読JSON。L1から一方向に生成し、手で直さない |

## 4. 母集団（網羅の分母）

- **都道府県**：47件（JIS X 0401 の都道府県コード順）。分母は固定で曖昧さがない。全件レコード化が完了条件。
- **市区町村**：総務省「全国地方公共団体コード」の現行市区町村一覧を制度的母集団とする。これに加え、地図データ（ユーザーの白地図 `detail` データ）に含まれる自治体名一覧を地図側の母集団として突き合わせ、差異（合併・改称・データ側の収載漏れ等）があれば理由つきで記録する。白地図側の実測は1,750件（都道府県名＋市区町村名の連結文字列が `name` 属性）。公式の市区町村数とは定義差がありうるため、一致を前提にしない。
- 収載率は層別（都道府県／市区町村）に報告し、混ぜた単一の％は出さない。

## 5. レコードスキーマ

```yaml
- id: "pref/13-tokyo"            # 都道府県は pref/、市区町村は muni/ + 都道府県コード付きスラッグ
  code: "13"                     # JISコード（市区町村は6桁コード）
  names:
    ja: "東京都"
    reading: "とうきょうと"
    aliases: []                  # 旧称・旧表記など事実としての別名のみ（江戸、東京府など）
  user_terms: []                 # 非専門家がこの地名を指す日常の言い方。レコード自身の内容に根拠があるものだけ
  naming_type: "新規命名"         # §2-2の類型：新規命名／一部の地名／藩名／文献から命名／合併新設／その他（理由を併記）
  prefecture: "東京都"            # 市区町村レコードのみ：所属都道府県
  homonyms: []                   # 同名の別自治体の id 一覧（§7）。なければ空
  summary: "2〜3文。その地名が何に由来し、県名・市名になった経緯の要約"
  first_attestation:             # 初出（名前の側）
    era: "慶応4年"
    year_western: 1868           # 不確かな場合は null にし、claims 側で幅を持たせる
    document: "江戸ヲ称シテ東京ト為スノ詔書"
    note: "初出の性格（命名そのもの／使用例の初出など）"
  claims:
    - text: "主張は1文1主張"
      kind: "fact"               # fact=歴史的事実として扱う主張／legend=民間伝説・伝承
      level: "E1"                # §6の証拠レベル。legend は「その伝承が記録されている」ことのレベルで付ける
      status: "established"      # established／contested／inferred／indeterminate／unknown
      sources: ["出典キー"]
  column:                        # ミニコラム（§8）。1レコードに0〜1件
    title: "コラム見出し"
    text: "読み物としての本文。事実と伝説の区別はここでも崩さない"
    sources: ["出典キー"]
  relations: []                  # 由来の元になった地名・関連自治体・同名自治体などの id
  unknowns: []                   # リスト形式必須。確認できなかったことと、その理由
  updated: "2026-11-13"
```

市区町村では原則として全項目を同じ形にする。政令指定都市の区は市区町村レコードとは別実体にせず、当面は母集団に含めない（区名の由来は親市のレコードのコラムまたは関係として触れる余地を残す）。

## 6. 証拠レベルと主張の状態

| レベル | 意味 | この分野での例 |
|---|---|---|
| E1 | 一次文献・一次記録そのもの | 『日本書紀』『続日本紀』『日本後紀』『和名類聚抄』、各国風土記、出土木簡、詔書・太政官布告・法令全書、藩・幕府の文書、自治体史が影印・翻刻で示す古文書 |
| E2 | 公的機関・学術機関の二次資料 | 都道府県・市区町村の公式サイトと自治体史（市史・町史の通史編）、国立国会図書館・国文学研究資料館・奈良文化財研究所のデータベース、博物館・大学の解説 |
| E3 | 専門文献 | 『角川日本地名大辞典』『日本歴史地名大系』、地名学の専門書・論文 |
| E4 | 地域の証言・郷土資料 | 郷土史家の著作、地域の広報・観光協会の解説 |
| E5 | 出典不明の一般情報 | 出典を示さないまとめサイト等。単独で主張の根拠にしない |
| H | 類推・仮説 | 調査者の類推。主張本文に混ぜず、status: inferred とし根拠を文章内に示す |

状態は established（確認済み）／contested（対立は両論併記）／inferred（類推）／indeterminate（調べたが決められない）／unknown（未確認）。

**一次文献への深追いの原則**：二次資料が「『続日本紀』にみえる」と書く場合、その記載自体を確認できた範囲で E1 とし、二次資料経由でしか確認できていない場合はレベルを E2 に落として「○○（自治体公式）が『続日本紀』の記載として紹介」と主張の形にする。原文を読めていない一次文献を、読めたものとして扱わない。

## 7. 同名地名の扱い

- 同じ読み・同じ表記の自治体は、**由来が同じとは限らない前提**で1件ずつ別レコードにする。id は都道府県を含めて一意にする（例：`muni/13-tokyo-fuchu`＝東京都府中市、`muni/34-hiroshima-fuchu`＝広島県府中市、`muni/34-hiroshima-fuchu-cho`＝広島県府中町）。
- 各レコードに `homonyms` で同名の相手を相互に挙げ、由来が同一か別かを claims で明示する（例：両府中とも律令制の国府所在地＝「府中」という普通名詞的地名に由来する点は共通でも、国（武蔵国／備後国）と成立事情は別、という形で「共通する層」と「異なる層」を分けて書く）。
- 「府中」「中野」「大和」のような普通名詞・国名・駅名等に由来する汎用地名は、総称を受け止める概念レコードを市区町村ドメイン側に置く余地を残す。

## 8. ミニコラム

事実の列挙だけでは読み物として弱いため、各レコードにミニコラムを原則1件付ける。

- テーマの例：命名の裏側の人間ドラマ（信長と「岐阜」）、政治的事情で改名された県名（仙台県→宮城県）、候補に残らなかった案（北海道の6案、西京）、現在の地名と原点の位置のずれ、伝説の語られ方の面白さ、同名地名どうしの意外な関係。
- コラムも出典を持ち、伝説は伝説と分かる書き方をする。コラムのために新しい事実を創作しない。書く材料が薄いレコードでは無理に付けず、unknowns 側に「コラムの材料未確認」と残してよい（ただし都道府県47件では原則付与を目指す）。

## 9. 地図とサイト

- 地図データの大元は国土数値情報（行政区域データ・2026年版）（国土交通省）であり、出典表記は国土数値情報を指す。データは同データを下敷きにしたユーザーの白地図（https://givemegohan.xyz/whitemap/）の GeoJSON を、本人の許可のもと引き抜いて取得した。投影法は白地図の方式（経緯度を線形に SVG 座標へ写像、viewBox 960級、マージン60）を踏襲し、見た目と操作感を揃える。
  - 都道府県レイヤー：`prefectures_simplified.geojson`（47件、`name` のみ、gzip 408KB／展開1.1MB）
  - 市区町村レイヤー：`detail_simplified.geojson`（1,750件、`name`＝都道府県名＋市区町村名、gzip 44MB／展開約171MB）。このままでは単一ファイルとしてブラウザに載せられないため、**都道府県別に47ファイルへ分割**して、深追いした県の分だけを読み込む方式にする。
  - 元サイトのデータには CORS ヘッダーがなく、他オリジンから直接 fetch できないため、データは本KBのサイト側に複製して置く（許可済み）。
- 画面構成：第1画面＝日本全図（都道府県）。クリックで右パネル（モバイルでは下部シート）に由来を表示し、「市区町村を深追い」ボタンでその県の市区町村地図へ遷移。市区町村をクリックするとその自治体の由来を表示。レコード未整備の自治体は「調査中」と正直に表示し、母集団上の位置づけ（planned）を示す。
- 検索（地名・読み・別名・user_terms 横断）と、naming_type・時代（初出の世紀）での絞り込みを付ける。
- OSM等のタイル地図は使わない。白地図SVGの方が地名のクリック選択と出典表示に適し、オフラインでも動くため。

## 10. 記法

- 数字・年は半角、西暦併記。年代表記は元号＋西暦を原則とする。
- 件数を散文で書くときは「現時点で○○件以上」の下限表記にする（サイトの統計表示はデータから自動計算されるものは除く）。
- 出典レジストリは1 URL＝1キー、未使用キーを残さない。紙の一次文献は URL なしを許容し、label に書誌（書名・巻・成立年など）を書く。
- 全レコードに `updated` を持たせる。`unknowns` は必ずリスト。
